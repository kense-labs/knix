# Image

`knix.img` 的唯一构建入口。固定输入来自 `platform/identity/`、`docs/brand/` 与 `virt.config`；seed qcow2 只作一次性包源与 helper 引导，不参与镜像内容。自编译内核、匹配模块与原生 rootfs 由 `build-kernel.sh` / `build-rootfs.sh` 在 arm64 Linux guest 内生成，各自产出 `kernel-build.json` / `rootfs-build.json` 记录摘要；`build.sh` 消费这些产物，组装出唯一镜像。`platform/host-adapters/` 不参与构建，也不进入产物。

| 文件 | 角色 |
| --- | --- |
| `manifest.json` | 构建配方：seed SHA512、18 个输入哈希（6 身份 / 4 品牌 / 5 配方 / 2 验证 / 1 锁定基线）、`build_baseline` 内核与 rootfs 锁定值，三阶段构建顺序、UEFI / 图形 / 帧缓冲契约与发布面 |
| `package-versions.txt` | 388 个已安装包的版本锁定清单（`dpkg-query` + `LC_ALL=C sort`），文本构建输入，不是二进制产物 |
| `build.sh` | 顶层编排；`--check` 校验全部输入哈希并运行 `verify-repro.py`，`--build` 建空白盘 → 逐字段校验锁定基线 → guest 内组装 → 冷启复验 → 写含 `baseline` 段的 receipt |
| `inject-identity.sh` | 把身份与品牌字节原样装进运行中的 guest |
| `build-rootfs.sh` | 在 guest 内用 `packages.json` 生成原生 rootfs、tarball、`rootfs-build.json`（schema 2）与 `package-versions.txt` 版本锁定清单 |
| `build-kernel.sh` | 在 guest 内原生编译 `repos/linux`：`--check` 校验 fragment 与内置启动驱动，`--apply` 产出 `Image.gz`、`knix-Image`、`modules/lib/modules/7.2.15` 与 `kernel-build.json`；检测到截断的构建树会自动清空重编 |
| `assemble-native.sh` | 在 guest 内建 ESP + root 双分区 GPT 盘，装原生 rootfs、自编译内核与 773 个模块，生成自有 initramfs 并把 systemd-boot / 内核 / initrd / loader entry 写入 ESP，写 `fstab` / 用户 / SSH / 网络、图形模块加载、virtio 输入 udev 规则、`knix-session.service` 与 `multi-user.target.wants` 自启 symlink，供 UEFI 自举 |
| `verify-graphics.sh` | 在冷启后的 guest 内以 root 证明 `knix-session.service` 已由 `multi-user.target` 开机启用且 active（脚本不负责启动），restart 取干净日志后验证 sway 以 `knix` 非 root 运行、seatd 提供 seat、`get_inputs` 返回 virtio 键鼠、virtio-gpu DRM 节点、GBM / GL 实际渲染与 `foot` Wayland 窗口，SIGKILL 后要求 guest systemd 恢复会话，最后让恢复后的 sway 画出 guest 自选的纯色图案；纯 shell，不依赖 guest 内的 python3 / jq |
| `verify-framebuffer.py` | 主机侧只读像素门禁：从 `guest-graphics.log` 读 guest 自选颜色，经 QMP `screendump format=ppm` 导出 P6 帧缓冲，硬校验 1280×800、9/9 采样点与 swaybar 像素；`--self-test` 用合成 PPM 跑 12 个用例，不需要 QEMU |
| `sign.sh` | 生成 receipt 校验和；提供密钥时追加 detached 签名 |
| `RELEASE.md` | 发布面、校验与回滚 |

`build-kernel.sh` 在 `olddefconfig` 之后把 virtio-blk / virtio-net / virtio-pci / ext4 / PL011 / devtmpfs 六项硬校验为 `=y`：自举路径在挂载根分区前不能依赖可加载模块，initramfs 也不打包这些驱动。图形驱动由脚本自己追加 `CONFIG_DRM_VIRTIO_GPU=m` / `CONFIG_VIRTIO_INPUT=m` 并硬校验 `CONFIG_DRM_VIRTIO_GPU_KMS=y`，不改写 `repos/linux/arch/arm64/configs/virt.config` 快照；模块文件是 `virtio-gpu.ko` / `virtio_input.ko`，`assemble-native.sh` 写 `/etc/modules-load.d/knix-graphics.conf` 让冷启自动加载，`kernel-build.json` 记录 `graphics_drivers` 与 `graphics_modules`。`modules_install` 落在构建盘的 `modules/` 下，由 `assemble-native.sh` 装进目标盘；`kernel-build.json` 记录内核版本、两个内核镜像的 sha256 与模块数量。编译前后都检查 `vmlinux.o` 的 ELF section header 表是否落在文件内，避免截断对象让 `modpost` 失败。`assemble-native.sh` 把 `modules/lib/modules/$KVER` 整目录复制进目标盘，版本从 `kernel-build.json` 读取，并用目标盘自身 rootfs 的 `depmod` 生成 `modules.dep`；模块缺失时组装直接失败。

`kernel-build.json` 还记录最终 `.config` 的 `config_sha256`；`assemble-native.sh` 把 `wireless-regdb` 的 alternative 切到上游签名变体，使 `cfg80211` 能用内核内置密钥验证 `regulatory.db`。`packages.json` 的 `boot` 集合提供 `systemd-boot-efi`（EFI 二进制）、`dosfstools`（ESP 格式化）与 `initramfs-tools`（生成 initrd），三者由 `build-rootfs.sh` 装进原生 rootfs；`KNIX_SETS` 默认包含该集合。

`build-rootfs.sh --apply` 在打包后用 `chroot dpkg-query` 导出 `package-versions.txt`（388 行，`Package\tVersion\tArchitecture`，`LC_ALL=C sort`），`rootfs-build.json` 记录它的 sha256 与行数。`build.sh --build` 把两份摘要和 lockfile 一起取回 host，与 `manifest.json` 的 `build_baseline` **逐字段**比对：内核版本、`config_sha256`、两个内核镜像 hash、模块数、图形驱动与模块名，rootfs tarball hash / 字节数 / 包集 hash / 包数 / 版本清单 hash / 版本行数，以及 guest lockfile 与仓内 `platform/image/package-versions.txt` 是否逐字节相同。任一漂移输出 `BASELINE DRIFT` 并中止，提示走 `scripts/refresh-baseline.py` 的三段式刷新。receipt 的 `baseline` 段记录 `build_baseline` 的规范化 sha256、内核/rootfs 锁定值、`package_lock` 路径与 `verified`，因此外部可以证明这张镜像来自哪一份锁定基线。

`knix-session.service` 的崩溃恢复由 guest 自己的 systemd 拥有：`Restart=on-failure` / `RestartSec=2` / `StartLimitBurst=5` / `StartLimitIntervalSec=30` 都由 `assemble-native.sh` 写进 unit 并在组装验收里逐项 grep；`session.json.resilience` 与 `manifest.json.graphics.resilience` 是两处机器真源。冷启验收完成首轮 DRM / seatd / sway / foot 验证后，`verify-graphics.sh` 用 `systemctl kill --signal=SIGKILL knix-session.service` 杀死合成器，等待 `MainPID` 变化，再要求重启后的 sway 仍属 `knix`、`get_inputs` 含 QEMU Virtio Keyboard / Tablet、`Virtual-1` active、GBM buffer 与 GL FBO 重新分配、foot 重新拿到窗口并提交 `wlr_surface`。unit 的 `ExecStartPre` 每次启动清空 `/run/knix-session.log`，因此这些渲染证据只能来自新进程；输出 `RESILIENCE VERIFY OK` 后 `build.sh --build` 才写 receipt，receipt 增加 `graphics.session.resilience`。重启限流避免坏掉的 sway 无限重启；`GPU=none` 时 DRM condition 不满足，unit 保持 inactive，串口与 SSH 仍是完整降级路径。

`scripts/refresh-baseline.py` 把刷新变成可评审的动作：`--check` 只读比对 guest 摘要、`build_baseline` 与全部输入哈希；`--propose` 把 rootfs 字段、输入哈希与 lockfile 的 old/new 连同四份指纹（kernel / rootfs 摘要、guest lockfile、manifest 字节）写进仓外 `BASELINE-PROPOSAL.json`；`--apply --reason "..."` 要求理由不少于 8 字符、提案未 applied、指纹未变、字段仍与当前摘要一致，才用定点替换写回 `build_baseline.rootfs` 与 `*_sha256` 输入组，必要时把 guest lockfile 同步进仓。**内核摘要漂移永远不由此脚本刷新**：内核变化会改变镜像本身，必须回到 `build-kernel.sh --apply`。`--self-test` 在临时目录里跑 12 个策略用例（漂移、提案、理由、篡改、过期、内核边界、lockfile 同步、幂等），不需要 seed 或 VM，因此作为 CI 的 `Baseline refresh policy` 步骤执行。

`build.sh --build` 先把旧 `knix.img` 移到 `.prev`，`qemu-img create` 一张 8 GiB 空白 qcow2，再以 `DISK=knix-helper.img EXTRA_DISKS="build-disk.qcow2 knix.img"` 启动 helper guest，把 `kernel-build.json` / `rootfs-build.json` / `knix-Image` 取回 host 后交给 `assemble-native.sh` 组装到 `/dev/vdd`。组装脚本逐项比对两份摘要与模块数量，输入漂移即失败。随后 `sync` + guest 内 poweroff，`boot-native.sh` 用干净 EDK2 变量存储做一次 **UEFI 自举冷启**（不传 `-kernel`、不挂 seed ISO，显式挂 `virtio-gpu-pci` 与 virtio 键鼠），复验身份、内核版本、模块数量、`modprobe`、品牌字节、零失败单元、cloud-init 残留、`cfg80211` 告警，以及 `/proc/cmdline` 的 `root=/dev/vda2`、ESP 上的 `BOOTAA64.EFI` / loader entry 与自有 initrd；冷启后的 guest verify 先硬校验会话 unit 已 `enabled` + `active`（证明开机自启而非被验收脚本拉起），随后把 `verify-graphics.sh` 以 root 流式送进 guest，由它 `systemctl restart` 取干净日志，硬校验会话用户、seat 标签、libinput 设备与实际渲染，输出 `AUTOSTART VERIFY OK` / `SESSION VERIFY OK` / `GRAPHICS VERIFY OK`。随后 `verify-framebuffer.py` 在 `stop_guest` 之前通过 QMP 读取 guest 刚绘制的帧缓冲并输出 `FRAMEBUFFER VERIFY OK`。任一步失败都中止构建，guest 侧打印诊断。最后才写 receipt，其中 `graphics` 段记录设备、验证脚本、`verified`、`graphics.framebuffer`（图案摘要、采样数与 swaybar 像素）与 `graphics.session`（用户、seat manager、unit、双 backend、输入设备与 autostart 结果）。guest 页缓存未 flush 会让写入随 VM 停止丢失，所有写入脚本都内置 `sync`。helper 启动显式 `GPU=none GPU_INPUT=none`，避免新增 PCI 设备改变 virtio-blk probe 顺序、挪动 `/dev/vdc` / `/dev/vdd`。

`build-rootfs.sh` 的覆盖变量：`KNIX_SETS`（默认全集）、`KNIX_VARIANT`（默认 `minbase`，包集由 `packages.json` 决定）、`KNIX_MIRROR`（默认 `http://deb.debian.org/debian`，QEMU slirp 下 HTTPS 并发下载会挂住）、`KNIX_DEB_CACHE`（默认关闭；仅用于本地复用已下载的 `.deb`，不是构建输入）。

`assemble-native.sh` 的目标盘必须是**新建的空白 qcow2**：从同一 seed 派生两张盘会带上相同的 ext4 UUID，guest 会把目标盘误认成根文件系统并挂到 `/`，格式化它就等于毁掉正在运行的系统。目标盘在 helper guest 里是 `/dev/vdd`，作为主盘自举时变成 `/dev/vda`：`/dev/vda1` 是 512 MiB FAT32 ESP，`/dev/vda2` 是 ext4 root，`fstab` 把 ESP 挂到 `/efi`，loader entry 的 `root=` 与 `fstab` 都指向 `/dev/vda2`。ESP 上是 `EFI/BOOT/BOOTAA64.EFI`（从 rootfs 的 `systemd-boot-efi` 包逐字节复制）、`EFI/knix/` 下的内核与 initrd、`loader/loader.conf` 与 `loader/entries/knix.conf`；initrd 由目标盘自身 rootfs 的 `mkinitramfs` 在 bind mount `/dev` / `/proc` / `/sys` 后生成，helper 用户态不进入产物。removable media path 不需要 EFI Boot#### 变量，因此干净固件变量也能启动。`knix.img` 就是组装的目标盘；`build.sh --build` 会先把旧镜像移到 `.prev` 再建空白盘，失败时可回滚。

`verify-graphics.sh` 只检查 guest 自有的东西：`/dev/dri/card0` 与 `renderD128`、`/sys/module/virtio_gpu` 与 `virtio_input`、`card0-Virtual-1` 的 1280×800 mode、`/dev/input/by-path` 的 virtio 键盘与指针、`knix.desktop` 的 `Exec=sway`；此外硬校验 `seatd.service` active、`knix` 属于 `video` / `input` / `render`、键鼠节点带 `seat` 与 `uaccess` 标签、`knix-session.service` 由 `multi-user.target.wants` 启用。它先在脚本触碰 unit 之前确认 `is-enabled=enabled` / `is-active=active` 且 sway 进程用户是 `knix`（输出 `AUTOSTART VERIFY OK`），再 `systemctl restart` 取干净日志，用 `swaymsg -t get_inputs` 要求 `QEMU Virtio Keyboard` 与 `QEMU Virtio Tablet` 都出现在 seat0 上。**不能**设置 `LIBGL_ALWAYS_SOFTWARE=1`（显式硬件 EGL device 与该变量冲突会让 Mesa segfault）。随后确认 `Virtual-1` active、日志里出现 `Allocated ... GBM buffer` / `Created GL FBO`，并 `swaymsg exec /usr/bin/foot` 让一个真实 Wayland 客户端出现在 `get_tree` 且提交 `New wlr_surface`。脚本不再 stop unit（`trap` 只 `reset-failed`），让开机自启的会话继续运行，输出 `SESSION VERIFY OK` / `GRAPHICS VERIFY OK`。unit 的 `WLR_BACKENDS=drm,libinput` 是关键：只写 `drm` 会排除 libinput backend，`get_inputs` 必然为空；`LIBSEAT_BACKEND=seatd` 让 guest 自有的 seat manager 提供设备 fd。unit 在 `[Unit]` 里 `After` / `Wants` 了 `systemd-udev-settle.service`，保证开机求值时 DRM 节点已就位。`GPU=none` 时 `ConditionPathExists=/dev/dri/card0` 不触发：实测 unit 仍是 `enabled` 但保持 `inactive`、0 个失败单元、无 sway 进程，串口与 SSH 保持可用。

像素证明由 guest 发起、主机只读：恢复后的 sway 关掉验收终端，用 guest 自己的 `/dev/urandom` 生成 24 位颜色（每通道抬到 `0x40..0xff`，避免黑屏误判），`output * background #RRGGBB solid_color` 画到标准 virtio-gpu scanout，并把 `FRAMEBUFFER PATTERN: <hex>` 打印到 `guest-graphics.log`。`platform/image/verify-framebuffer.py` 只连 QMP socket、发 `qmp_capabilities` 与 `screendump format=ppm`，解析 P6 PPM 后要求 1280×800 / maxval 255 / 完整像素字节、9 个采样点全部等于 guest 报出的颜色、顶部 24 行有至少 100 个非图案像素（guest swaybar）。它不绘制、不注入、不配置 guest 内容，也不写回镜像；产物 `framebuffer.ppm` 与 `framebuffer-verify.json` 都落在 `$KNIX_DEV_DIR`。注意 SSH 会话结束时 logind 会清空 `/run/user/1000` 并删掉 sway 的 IPC socket，但已绘制的像素保留在 scanout 上，因此抓帧完全不需要 guest socket；图案必须在 `stop_guest` 之前抓取。

`.github/workflows/knix-contract.yml` 在 Linux CI 上跑 10 个步骤：协作门禁（`verify-knix.py`，含 I18 会话契约、I19 开机自启契约与 I22 像素契约）、可复现性门禁（`scripts/verify-repro.py`）、后端边界门禁（`scripts/verify-backends.py`）、基线刷新策略自测、帧缓冲像素自测、单镜像 / UEFI / 图形 / 会话 / 帧缓冲 / 锁定基线契约、shell 与 Python 脚本语法、内核 fragment 与包集解析。`verify-repro.py` 还检查 `platform/` / `scripts/` / `docs/` / `.github/` 内没有 `.img` / `.qcow2` / `.zst` / `.fd` / `.ppm` 等二进制构建产物。seed qcow2、QEMU/HVF 启动、镜像组装、UEFI 冷启与 sway 实际渲染只在本地构建机执行，CI 不下载它们，也不跑完整构建（seed 不入库、HVF 只在 macOS 可用）。

镜像与 receipt 落在 `$KNIX_DEV_DIR`（默认仓外同级 `knix-m0/`），不入库。仓内只有可复现的定义与哈希；`origin/main` 是唯一发布面。receipt 的 `sha256` / `bytes` 对应构建完成那一刻的镜像：qcow2 可写，任何后续启动都会改变字节，所以写完 receipt 后不再启动发布镜像；额外验收用 `qemu-img create -b knix.img -F qcow2` 的 overlay 副本，并复核 backing 镜像哈希未变。

构建不改变 `repos.json` 的 `count`、`snapshot_sha`、`snapshot_files`、`snapshot_bytes` 或 `totals`。
